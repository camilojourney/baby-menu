Baby Menu recipe

Antigravity quota

Build a user-installed widget that reads both weekly model groups from the real agy /usage terminal screen. This recipe is self-contained and does not require an external codebase or guide.

Capability

Show Gemini models and Claude + GPT models as separate weekly quota buckets. Display percent used and remaining, the Google AI plan when present, a checked timestamp, and an explicit unavailable error when live capture fails. Never fabricate quota and never describe an idle prompt as consuming quota.

Expected user-facing behavior

  • Refresh only while the widget is visible, using the slowest acceptable interval of five minutes.
  • Keep the last good result visibly stale when a later refresh fails.
  • Distinguish unavailable, sign-in-in-progress, timeout, oversized or malformed output, and parse failures.

Recommended Data Source Order

  1. Run the installed agy CLI in a pseudo-terminal and open /usage.
  2. Parse only the final rendered screen after terminal escape sequences are removed.
  3. If the named source is unavailable, return a structured error. Do not substitute sample data.
Inspect the real named CLI with redacted output before writing or changing the parser. Never print credentials or raw provider data.

Implementation Contract

Put filesystem, shell, process, and terminal access in antigravity-quota/server.ts behind window.babyMenu.capabilities.invoke("antigravity-quota", "getQuota"). Do not add a preload method. Keep renderer state in store.ts, components in components.tsx, and the descriptor in widget.tsx. Copy the shipped sibling template recipes/antigravity-quota.template.ts to the extension's server.ts rather than recreating its process ownership logic.

Process ownership

  • Spawn the Python PTY helper from Node with detached: true.
  • Give the helper a dedicated host-liveness pipe on fd 4. Launch agy without start_new_session=True and with inherited descriptors closed, so helper and CLI stay in the same process group but only the helper owns the liveness pipe.
  • After success or timeout, signal -child.pid with SIGTERM, allow a three-second grace period, then signal the same group with SIGKILL.
  • Install a Python SIGTERM handler so its finally block can terminate and reap agy, then keep the helper alive after reporting its outcome until Node escalates. The live group leader anchors the PGID so it cannot be recycled during the grace period.
  • Monitor fd 4 during capture and every anchor state. EOF proves the Node host exited, so the still-live group leader must signal its own PGID with SIGTERM, wait only the configured grace period, and then SIGKILL the group. Do not independently exit the helper while the lease remains open because a delayed Node timer could otherwise signal a recycled PGID.
  • Put all Python work after Popen inside try/finally, and wait after both terminate and kill so normal helper exit proves agy was reaped.
  • Use a 35-second internal capture deadline and a 50-second Node timeout, leaving cleanup and encoding margin.
  • Keep only a rolling 128 KiB raw PTY tail. Do not kill the helper merely because a redrawing TUI crossed a Node output cap.
  • Do not sweep historical bare agy processes. A shared cwd, command name, or Baby Menu ancestor cannot prove ownership and could match a real user or worker session.

Parser contract

Strip OSC, CSI, and control sequences. Parse GEMINI MODELS and CLAUDE AND GPT MODELS, each followed by Weekly Limit and a percentage. Clamp remaining percentage to 0 through 100 and compute used as 100 - percentRemaining. Capture a parenthesized Google AI ... plan when present.

Source outcomes

Report a missing agy executable as Antigravity CLI is unavailable, an installed source that exits without a complete quota frame as Antigravity quota is unavailable, and an active browser authentication flow as Antigravity sign-in is in progress. The sign-in-in-progress result is transient and must not be replaced by a hard failure or timeout. Keep the separate capture-timeout and malformed-frame results.

Server action response shape

type Result =
  | { ok: true; data: {
      source: "agy /usage";
      plan?: string;
      checkedAt: string;
      buckets: Array<{
        id: "gemini" | "claude-gpt";
        label: string;
        percentUsed: number;
        percentRemaining: number;
        windowLabel: "weekly";
      }>;
    } }
  | {
      ok: false;
      status: "missing-agy" | "unavailable" | "sign-in-in-progress" | "timeout" | "malformed-output" | "python-unavailable" | "capture-failed";
      error: string;
      transient?: true;
    };

Acceptance criteria

  • An end-to-end process test proves timeout escalation leaves no fake agy descendant alive.
  • A host-exit test SIGKILLs Node during capture and proves fd 4 EOF triggers bounded self-cleanup of the helper, agy, and a surviving descendant.
  • A successful capture test proves process-group cleanup leaves no fake agy descendant alive while preserving decoded quota output.
  • A timeout test proves the helper remains the group leader until escalation, preventing a stale PGID signal.
  • A redraw test emits more than 256 KiB, returns successfully from the rolling tail, and preserves both quota buckets.
  • Focused tests preserve distinct missing-CLI, unavailable-source, sign-in-in-progress, internal-timeout, and outer-timeout results.
  • Tests preserve the normalized response shape and verify no other quota extension is modified.
  • Verify the completed server action against the real agy /usage source using redacted output only.
